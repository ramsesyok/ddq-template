# 自動分割表のページ通番修正の検証（2026-10-22）

対象ブランチ: `fix/table-pagination-range`。比較元: `dca4f1208e21e79ea0aaa402a9aedd81cb73e343`。
検証環境: Linux、Quarto 1.9.38、同梱 Typst 0.14.2、Rust 1.95.0。

## 問題と修正

従来の `_tbl-auto` は、先頭セル・末尾セルの共通ラベルを現在位置の前後から探索していた。
行内改ページを許可した表では、末尾列が短く、中間列だけが複数ページに続く場合に
自分の終点を拾えず、分割通番が消えたり、後続表の範囲を参照して負数になったりした。

修正後は表グループ専用カウンタで各表を識別し、繰り返しキャプションに配置する
`metadata` の物理ページを集計する。セルの高さ・列順・後続表の有無に依存しない。
手動分割は `first: true` のパートでグループを開始し、後続パートも同じ番号で集計する。
関数の引数は維持し、図表番号のカウンタ・相互参照・列幅・行内改ページの可否は変更しない。
docgen の表種別による分岐や変更はない。Lua の変更は処理説明のコメントのみ。

## 修正前後の再現

同じ原稿と同じ環境で `lib.typ` だけを差し替え、PDF の実際の表示を比較した。

| 条件 | 修正前 | 修正後 |
|---|---|---|
| 中間列だけが高い単独表（5ページ） | 分割通番なし | 1／5〜5／5 |
| 同じ表の後ろに別の長い表 | 継続ページで −3／5〜0／5 | 各表で独立して1／5〜5／5 |
| 最終行だけが高い複数行の表（6ページ） | 分割通番なし | 1／6〜6／6 |

表番号そのもの・キャプション全体が消えるという報告は未再現。
回帰テストでは、本文が存在する全ページに表番号とキャプションが出ることも検査する。

## 自動テスト

`cli/tests/table_pagination.rs` と `fixtures/table-pagination.{typ,qmd}` を追加した。
内部のページ集計用 metadata を検査するのではなく、描画された文字列とその物理ページから
本文の範囲を求め、キャプション・表番号・通番・総数・末尾の本文を照合する。

15パターン: 先頭列／中間列／末尾列が高い表、後続表、最終行が高い表、同一ページ上の隣接表、
手動分割、通常表、多数行（行内改ページ禁止）、ヘッダなし、番号なし、ヘッダのみ、結合セル、
前方・後方参照、Quarto → Lua → Typst の統合経路。
統合経路ではグリッド表・横向き・手動分割・自動結合・番号なし表・開始ページ番号7を併用する。
レイアウト未収束の警告も失敗として扱う。

```sh
DDQ_E2E=1 cargo test --locked --test table_pagination
```

## CLI全体の検査

テストターゲットを分けて最後まで実行し、合計126件が成功した。
`cargo fmt --check` と `cargo clippy --all-targets -- -D warnings` も成功。
以下の既存2件はLinux上で失敗するため、今回の修正の検査結果と区別する。

| 既存テスト | Linux上での失敗理由 |
|---|---|
| `serve_answers_serverinfo_and_stops_with_parent` | Windows Job Object による親終了時のJVM停止を前提とする。修正前の ddq でも、親終了後の `/serverinfo` がHTTP 200で応答することを確認した |
| `zip_matches_the_stage_byte_for_byte` | 配布物の実行ファイル名を `ddq.exe` と決め打ちしている。既存の実装は起動した実行ファイル名を使うのでLinuxでは `ddq` になる |

新規回帰テスト、ASCII／非ASCIIパスでのPDF・HTML生成、改訂・タグ・ライセンス検査は成功。
`cli/vendor/plantuml.jar` は既存の配布用MIT版（vendor/README.md記載のSHA-256と一致）を置いて照合した。
対応範囲を一括して再実行する場合のコマンドは以下。

```sh
DDQ_E2E=1 cargo test --locked -- --skip serve_answers_serverinfo_and_stops_with_parent --skip zip_matches_the_stage_byte_for_byte
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
```
