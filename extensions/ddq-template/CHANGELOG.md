# 変更履歴

## 3.1.0（2026-11-23）

3.1 系の正式版です。3.0.0 から移る場合は、下の 3.1.0-pre1 の変更もあわせて読んでください。pre1 からの変更は次のとおりです。
**機構ファイル（`design-doc.lua`・`postprocess-html.js`）が変わるので、既存の執筆フォルダは `ddq update` が要ります**
（出力の時の通知から実行できます）。

- 同梱の `ddq.exe`（章の並び）: `_quarto.yml` の `book.chapters`・`book.appendices` を、Quarto が描くのと同じ並びに読むようにした。
  これまでは、行末にコメントのある章・引用（`"…"`・`'…'`）や空白を含むパス・`part:` で束ねた章・キーと同じ字下げで書いた列・
  フロー形式（`[a.qmd, b.qmd]`・`{part: …, chapters: […]}`）・`href:`・`file:` で書いた章・`book.references` のページを読み落とすことがあり、その章の見出し・図表がラベルの候補・改訂の差分・
  HTML の番号の対象から抜けていた。`part:` にファイルを書いた部の扉ページも対象になる（HTML の図表の番号は、番号なしの章と同じく
  「図 0-1」）。付録は `_quarto.yml` に書いた順にかかわらず章の後ろ、`index` はどこに書いても先頭（Quarto と同じ）。
  既存の `_quarto.yml` は書き換えない
- 新規作成の雛形: `ddq init` / `ddq add`（VSCode の「設計書リポジトリを作成」）が置く雛形を、記法見本つき（1 章は概要、2〜7 章は
  基本・文書の組み立て・表・図・横向きページと IPO 図・相互参照）にし、章・節のフォルダ名を `chapters/01` のような番号だけにした
- 同梱の `ddq.exe`（原稿・改訂ファイルの書き込み）: `ddq tag apply` が原稿の BOM を残すようにした（これまでは落とした）。書く前に、一覧を
  作った後で中身が変わっていないかを照らし、同じフォルダの一時ファイルから置き換える（途中で止まっても書きかけのファイルにならない）。
  ほかのプログラムが書き込み用に開いたままのファイルは、1 秒ほど待っても閉じなければ書かずに止める（その間に保存された内容は消さない）。
  一時ファイルを書けないときは元のファイルに触れない。書けないファイルがあると分かっていれば何も書かずに止め、途中で失敗したときは
  書いたファイルと書いていないファイルを挙げる。`ddq rev diff --write` も、途中で改訂ファイルが保存されたら書かずに止める
- 同梱の `ddq.exe`（作成と更新）: `ddq init` / `ddq add` は、同時に作られたものを含め既にあるファイルを上書きしない。`ddq update` は
  機構ファイル → 図のキャッシュ → 版マーカーの順に書き、キャッシュを消しきれないとき・`diagrams` を読めないときは版マーカーを古いまま
  残して終了コード 1 で止まる（再実行すれば最後まで終わる）
- 同梱の `ddq.exe`（改訂履歴）: 改訂ファイルの引用付きの値の逆斜線が、保存するたびに増えなくなった（Rust と拡張で同じ読み方にした。
  旧拡張で増えた分は書かれたとおりに読むので、直すときは Git の差分を見て手で戻す）。改訂履歴の表（`ddq rev build`）で、修正内容に
  書いた `C:\docs` のような逆斜線が書いたとおりに出る（表は `ddq rev build` をやり直すと新しくなる）
- 同梱の `ddq.exe`（ラベル）: 同じファイルに、ラベルの無い同じ種類・同じ題名の項目が 5 つ以上あると `ddq tag list` が落ちていたのを直した
  （5 つ目からの候補は `-2`・`-3`…を付ける）
- 同梱の `ddq.exe`（図）: タブを含む mermaid の図も、先回りで描いた SVG を使う（これまでは 1 図ずつ描き直していた）
- 拡張（改訂履歴の画面）: 開いた直後、タグの状態を確かめ終わるまでは編集できない（確定済みの改訂を直せてしまうことがあった）。
  保存できなかったときは、差分の取り直し・確定に進まない。ほかのエディタなどで直したメモを、古い画面の値で戻さない（打った行が
  ほかで変わっていたら当てずに知らせ、画面を文書の内容に戻す）
- 拡張（表エディタ）: `merge-cols="ALL"`・`merge-cols=""`・旧 `.merge-rows` の表を、文書の出力と同じく結合せずに開く（これまでは全列を
  結合して開き、書き戻すと文書でも結合されるようになった）。解釈できない `merge-cols` は警告する
- 拡張（版の案内）: 版を `preN` まで番号順に比べる。pre の文書を新しい ddq で発行すると「テンプレートが古い」として `ddq update` を
  案内し、文書の方が新しいとき・版が分からないときは update を勧めない（これまでは、機構を古い版に戻す update を勧めることがあった）
- 拡張（ほか）: ステータスバーの執筆フォルダの表示が、エディタを続けて切り替えたときに前のフォルダに戻らない。発行を中止したとき、
  ddq が起動した子孫のプロセス（Quarto など）まで止める（Windows）
- 配布: VSIX にも `THIRD-PARTY-NOTICES.md` を入れた（ZIP と VSIX のファイル一覧の差は、VSIX 側の 1 ファイルの追加だけ）
- 開発: 配布候補（ZIP と同梱版の VSIX）は GitHub Actions（`release-candidate.yml`）が作って別のランナーで検査し、すべて通った実行の
  成果物だけを公開に使う（利用マニュアル 18 章）。リリース一式を作るコマンドは ddq から外し、保守者用の `ddq-release` にした
  （`ddq release` は無くなった。配る `ddq.exe` の動作は変わらない）

## 3.1.0-pre1（2026-11-17、プレリリース）

- 同梱の `ddq.exe`（記法）: 番号付きリストの項目を参照できるようにした。項目の行末に `{#num-x}` を書き、
  本文で `@num-x` と参照する（見出しの `{#sec-x}` と同じ書き方）。表示は参照先の項目の記号そのもの
  （PDF は (3)・②・(ア)…、HTML は数字）。章をまたぐ参照、表のセル・callout の中の項目にも効く。
  重複と参照先なしは警告する。あわせて、PDF で途中の番号から始まるリスト（4. から再開など）の記号が
  「4.」になっていたのを (4) に直した（機構ファイル `design-doc.lua`・`postprocess-html.js` が変わるので `ddq update` が要る）
- 同梱の `ddq.exe`（番号）: コード（`lst-`）と数式（`eq-`）の番号を PDF と HTML で揃えた。コードは両方とも
  図表と同じ「章.節-連番」になる（PDF は連番が節で 1 に戻らず、HTML は Quarto 既定の「コード 1.1」だった）。
  数式の HTML の参照は、式の右の番号と PDF に合わせて「式 (1.1)」にした
- 同梱の `ddq.exe`（PDF の様式）: `toc: true` のとき、PDF の目次を前付け（`index.qmd`）の後ろ・第1章の前に
  置くのを既定にした。並びは「（表紙）→ 前付け → 目次 → 本文」になり、前付けの見出しは目次に載らない。
  従来どおり表紙の次に出すには `_quarto.yml` に `toc-position: top` を書く。前付けに `#design-toc()` を
  書いた場合は `toc: true` のままその位置に目次が出る（これまでは `toc: false` にしないと目次が 2 つ出た）。
  HTML は変わらない（機構ファイル `design-doc.lua` が変わるので `ddq update` が要る）

## 3.0.0（2026-11-15）

3.0 系の正式版です。2.x から移る場合は、下の 3.0.0-pre1〜pre4 の変更もあわせて読んでください
（拡張の統合・ddq.exe の同梱・書体の統一など）。pre4 からの変更は次のとおりです。

- **配布 zip（`quarto-template-<版>.zip`）に `plantuml.jar` を同梱しないようにした。** PlantUML の版・ライセンス・
  脆弱性への対応を、利用する組織の判断で行えるようにするため。PlantUML 図をローカルで描く人は、PlantUML の公式リリース
  から jar（MIT 版を推奨）を取得し、環境変数 `DDQ_PLANTUML_JAR` にそのパスを設定する（利用マニュアル 11 章）。
  以前の版の zip の jar を使っていた端末は、新しい版に入れ替えると「plantuml.jar が見つかりません」で止まる。
  LAN 内の PlantUML サーバを使う場合と、PlantUML 図を使わない文書には影響しない。拡張・ddq の設定は変わらない
- 同梱の `ddq.exe` が内蔵する mermaid を 11.16.0 → 11.16.1 に上げ、中に固めてある依存を修正版に入れ替えた。
  mermaid の既知の脆弱性 5 件（XY チャート・レーダー図の無限ループ、図の外へ効く CSS の注入、プロトタイプ汚染 2 件）と、
  npm の mermaid の配布物に入っていた DOMPurify 3.4.0・KaTeX 0.16 の既知の脆弱性を解消した（DOMPurify 3.4.18・
  KaTeX 0.18.10）。npm の `mermaid.min.js` をそのまま使うのをやめ、`cli/tools/mermaid-bundle` で lock の依存から
  束ね直す（図の形は 11.16.1 の公式の配布物と同じ）。`THIRD-PARTY-NOTICES.md` の mermaid の一覧は、束ねた JS に実際に入った
  パッケージ（esbuild の metafile による）だけにした。この mermaid は PDF・配布 HTML 用の図を描くときに端末のブラウザで動く（HTML には入らない）
- 依存の更新: `zip` 9.5.1（展開時のシンボリックリンク・権限の扱いの脆弱性 4 件。ddq は展開に使わないが、
  `cargo audit` で 0 件にする）、`pulldown-cmark` 0.13.6（mermaid の内蔵レンダラ経由）、`rustix` 1.1.6、
  拡張の開発用ツール（vite・vitest、`@vscode/vsce` が使う glob 14・minimatch 11。VSIX には入らない）
- 開発: `ddq release` が、`node_modules` があっても必ず `npm ci` してから VSIX を作るようにした
  （古い `node_modules` の依存が VSIX に入らないように）
- 開発: CI で、同梱の mermaid.min.js の依存を `npm audit` で検査し、lock から作り直したものと一致するかを確かめる。
  `cargo audit` も CI で回す
- 開発: CI の実拡張ホストの検証を、同じコミットからビルドした本物の ddq で回すようにした。これまで差し替えで
  飛んでいた改訂履歴の編集画面・発行・作成・追加も CI で確かめる
- 開発: 表エディタの画面（選択・編集・ツールバー・属性欄・列幅・右クリックのメニュー・Undo・
  コピー／貼り付けと Apply で渡す中身）を jsdom のテストで確かめるようにした
- 同梱の `ddq.exe`: PlantUML サーバの宛先に `localhost` を使うと繋がらなかった問題を修正
  （`ddq plantuml serve --bind localhost`、`PLANTUML_SERVER=http://localhost:…`。IPv6 のアドレスにだけ繋いでいた。2.2.0 から）
- テンプレート（`design-doc.lua`）: 英語版 Windows など、ロケールが日本語でない端末で IPO 図の「入力」「出力」の
  見出しを読めず、入力の列が消えていた問題を修正。旧記法「機能 / 処理」で「システム」のように末尾が欠ける
  名前も直した（日本語の文字列に、ロケールで動きが変わる大文字小文字の変換と空白の判定を使っていたため）。
  既存の設計書リポジトリでは `ddq update` が必要
- 開発: 通知・ダイアログの操作（作成・追加の名前入力とフォルダ選択、発行の完了・失敗・版不一致・
  Quarto 不在の通知のボタン、キャンセル）と、右クリックメニューの `when` 句をテストで確かめるようにした。
  実拡張ホストの検証に PDF の作成を足した

## 3.0.0-pre1（2026-10-27、プレリリース）

**ddq-revision と ddq-table-editor を 1 本の拡張 DDQ Template（`ramsesyok.ddq-template`）に統合しました**
（docs/ddq-template-study.md）。機能は両拡張と同じです。

**挙動が変わる点**:

- 拡張 ID が `ramsesyok.ddq-template` になります。旧 `ramsesyok.ddq-revision` /
  `ramsesyok.ddq-table-editor` が入っていると、起動時にアンインストールを案内します
  （同じファイルに既定の編集画面が 2 つ登録され、メニューも重複するため）
- コマンド ID とコマンドパレットの表記が変わりました。キーバインドを付けていた場合は付け直してください

  | 旧 | 新 |
  |---|---|
  | `ddqRevision.tags`（DDQ Revision: 見出し・表・図のラベルを一覧する） | `ddqTemplate.tags`（DDQ: 見出し・表・図のラベルを一覧する） |
  | `ddqRevision.newRevision`（DDQ Revision: 新しい改訂を始める（差分を取る）） | `ddqTemplate.newRevision`（DDQ: 新しい改訂を始める（差分を取る）） |
  | `ddqTableEditor.open`（DDQ Table Editor: Open Table Editor） | `ddqTemplate.openTableEditor`（DDQ: 表エディタを開く） |
  | 改訂履歴の編集画面 `ddqRevision.editor` | `ddqTemplate.revisionEditor` |

- 設定 `ddqRevision.ddqPath` は **`ddqTemplate.ddqPath`** になりました。値は引き継がないので、
  設定していた場合は入れ直してください
- 信頼されていないワークスペース（制限モード）では動きません（ワークスペースで ddq を実行するため）
- ラベル一覧・改訂履歴の対象になる執筆フォルダは、`_quarto.yml` に加えて `.template-version` が
  あるフォルダになりました（素の Quarto プロジェクトと見分けるため）
- ラベル一覧・改訂履歴の右クリックメニューは、執筆フォルダとその中のフォルダにだけ出るようになりました
- 設定 `ddqTemplate.ddqPath` に `.cmd` / `.bat` を指定しても起動しません（引数のフォルダ名などを
  cmd.exe が解釈してしまうため）。`ddq.exe` を指定してください
- ラベルの書き戻しは、一覧を取ったあとにその行の中身が変わっていたら飛ばします（行番号が残っていても）。
  旧版は既にラベルがあるかだけを見ていたので、見出しを段落に書き換えると段落の中に挿入していました。
  照合用の行を返さない古い ddq を `ddqTemplate.ddqPath` に指定している場合は、ラベルを書き戻しません
  （一覧を開いたときに警告します）。設定を空にして同梱の ddq を使ってください

**ddq.exe を同梱しました**: 配布する VSIX は Windows x64 向けの `ddq-template-win32-x64-<版>.vsix` で、
ddq.exe が入っています（ddq を別に入れなくても使えます）。配布 zip（`quarto-template-<版>.zip`）には
VSIX を入れず、リリースページに別の資産として載せます。

**設計書リポジトリを VSCode から作れるようになりました**:

- コマンド **DDQ: 設計書リポジトリを作成**（`ddq init`）。フォルダを開いていなければ作る場所を選んで
  作成し、そのフォルダを開き直します。空のフォルダを開いていればそこに作ります
- フォルダを開いていないときのエクスプローラに、作成のボタンが出ます
- 作り終えると `_quarto.yml` を開き、**Git リポジトリとして初期化** を案内します
- ddq init が置く `.vscode/extensions.json` で、Quarto 公式の拡張（`quarto.quarto`）を
  おすすめに出します（自動では入れません）

**発行（PDF / HTML / 図）を VSCode から行えるようになりました**:

- コマンド **DDQ: PDF を作成** / **DDQ: HTML を作成** / **DDQ: 図を変換**。執筆フォルダの右クリックと、
  ステータスバーの `PDF: <執筆フォルダ名>` からも実行できます
- 出力は「出力」パネルの DDQ に流れ、進捗の通知からキャンセルできます。同じ執筆フォルダでは 1 本ずつ
- テンプレートの版が合わないと、版を比べて **ddq update を実行** を案内し、更新後に元のコマンドを
  やり直します（執筆フォルダの方が新しいときは update を出さず、拡張の更新を促します）。
  **ddq の更新が必要です**（版不一致を終了コード 3 で返す ddq）
- 使う ddq は「設定 `ddqTemplate.ddqPath` → 拡張に同梱した ddq.exe → `PATH`」の順に決まります
- Quarto が見つからないと案内を出します。設定 `ddqTemplate.quartoPath` で quarto.exe を指定できます

版はテンプレートと揃え（0.2.0 → 2.1.0）、以後はリリース一式（`quarto-template-<版>.zip`）に
`ddq-table-editor-<版>.vsix` として同梱されます。

**挙動が変わる点**:

- コマンド ID が `quartoTable.open` → `ddqTableEditor.open`、コマンドパレットの表記が
  **DDQ Table Editor: Open Table Editor** になりました。キーバインドを付けていた場合は

テーブル編集の操作感を [vscode-edit-csv](https://github.com/janisdd/vscode-edit-csv)
（Handsontable）にそろえた版です。

**挙動が変わる点**（既存の使い方に影響します）:

- 編集中の **Escape が「取り消し」**になりました（従来は確定）。確定は Enter / Tab、
  または別のセルのクリックです
- Enter で確定すると**下のセルへ移動**します（従来はその場に留まる）
- セルを選んで**文字を打つと、内容を置き換えて編集が始まります**（Excel と同じ）。
  末尾に追記したいときは Enter / F2 / ダブルクリックで入ってください
- 「行を追加」「列を追加」が**上／下・左／右**に分かれました

#### セル操作

- **キーボード移動**: 矢印キー、Tab / Shift+Tab（行末で折り返し）、Home / End、
  Ctrl+Home / Ctrl+End。結合セルは飛び越える
- **範囲選択**: ドラッグ、Shift+矢印、選択の右下の ■（フィルハンドル）のドラッグ、Ctrl+A。
  結合セルに掛かる範囲は結合セル全体まで広がる。■ は選択を広げるだけで値はコピーしない
- **Delete / Backspace** で選択範囲の内容を消去（結合は崩さない）
- **Undo / Redo**: Ctrl+Z ／ Ctrl+Y（Ctrl+Shift+Z）とツールバーのボタン。セル編集・
  行列操作・結合・貼り付け・属性・列幅・揃えをすべて戻せる
- **右クリックメニュー**: 行の挿入（上／下）・削除、列の挿入（左／右）・削除、結合・解除、
  内容の消去、元に戻す／やり直す
- IME の変換途中で入力が途切れないよう、編集用の入力欄を 1 つに固定して常にフォーカスを
  持たせる作りにした（Handsontable と同じ）

### 0.2.0 — 2026-08-14

セル内に**箇条書き・番号付きリスト・段落**を書けるようにした版です。あわせて報告された
不具合（セル内改行・列幅の検査・F2）を直し、セルのコピー／貼り付けを Excel の操作感に
そろえました。

**挙動が変わる点**（既存の使い方に影響します）:

- セルを選んだ状態の Ctrl+V が、表全体の置き換えではなく**選択位置への貼り付け**になりました。
  表全体を置き換えるときは Escape で選択を解除してから貼り付けてください
- **セル内改行を含む表はグリッド表で出力**されます（従来はパイプ表＋`<br>`）
- セル本文を**マウスで選択できなくなりました**。文字を選ぶには編集モードに入ってください

#### 修正

- セル内で改行できない不具合を修正（[#4](https://github.com/ramsesyok/quarto-table-support/issues/4)）。
  textarea は Alt+Enter では改行しない（改行が入るのは修飾キー無しの Enter だけ）ため、
  改行の挿入とキャレット位置の復帰を自前で行うようにした

#### セル編集

- 選択セルで **F2** を押すと編集モードに入るようにした（Excel と同じくキャレットは末尾。
  [#3](https://github.com/ramsesyok/quarto-table-support/issues/3)）
- 編集中の入力欄が、中身の行数に合わせて自動で伸縮するようにした
  （改行したときに下の行が隠れないように）
- Shift+クリックの範囲選択やセルをまたぐドラッグで、ブラウザ標準のテキスト選択が
  青く塗られないようにした（範囲選択と紛らわしいため）。編集モードでは従来どおり
  文字を選択・コピーできる

#### クリップボード

- **選択セルを Ctrl+C でコピー**できるようにした。形式は Excel と同じ TSV で、改行・
  タブ・`"` を含むセルは `"…"` で囲む。結合に吸収されたセルは空にする
- **Ctrl+V を選択位置への貼り付けに**した（Excel と同じ）。値が 1 つだけなら選択範囲を
  すべて埋めるので、○ / × のような値を表の中で使い回せる。はみ出す分は行・列を足す。
  結合に吸収されたセルには書き込まず、捨てた数をメッセージで知らせる
- 選択していないときの Ctrl+V は従来どおり表全体の置き換え（Excel からの取り込み）。
  タブを含むテキストだけを受け付ける点も従来どおり
- **Escape で選択を解除**できるようにした（表全体の置き換えに戻る道）

#### 列幅（`widths`）の検査（[#2](https://github.com/ramsesyok/quarto-table-support/issues/2)）

- 合計が 100 を超える／負の値があるときは入力欄を赤くし、Apply を拒否する
- 空欄が 1 列だけのときは、Apply とプレビューの直前に残り幅（100 − 他列の合計）を
  自動で入れる

#### 出力形式

- **セル内改行がある表はグリッド表で出力する**ようにした。パイプ表では改行が `<br>` に
  なり、箇条書き・番号付きリストをセルに置けないため。`merge-cols` を選んでいるときは、
  結合を展開した素のグリッド表にする（フィルタ側で結合される）
- グリッド表の改行 `\` を、リスト項目どうしと空行の前後には付けないようにした
  （付けると項目末尾に余分な改行が入るため）
- 文章行の直後にリストを書いたときは、書き出し時に空行を補うようにした。pandoc は
  リストで段落を中断しないため、空行が無いと `- 項目` が文字のまま出てしまう。
  エディタ上は空行なしで書ける（補った空行は読み戻しで畳むので往復で増えない）
- グリッド表のセル内の空行（段落区切り）を読み書きで保つようにした
- セル内の行頭の空白を保持するようにした（入れ子リストの階層・項目内折り返しの字下げ）。
  リスト項目の続きは `\` を付けて項目本文の桁まで下げて書き出す
- コード span（`` `…` ``）の中の `<br>` を改行に変換しないようにした
  （`<br>` を文字として説明するセルが壊れていた）
- 行末のバックスラッシュが `\\` と重なっている表を、開いて書き戻すと直すようにした。
  `\\` はエスケープされたバックスラッシュとして扱われ、改行が消えて `\` が文字として
  出てしまう。モデル側に残った行末のバックスラッシュも書き出し時に落とす
- エディタのセル表示で行頭の空白を潰さないようにした（入れ子リストの階層が見えるように）

### 0.1.0 — ベータ版（初回リリース）

`design-doc-quarto-template` の統一テーブル記法 `::: {.tbl …}` を視覚的に編集する
VSCode 拡張の最初のリリースです。ベータ版のため、実運用の前にファイルをバージョン
管理下に置くことをおすすめします。

#### 機能

- `.tbl` ブロックの再編集（`.tbl` 自体をマーカーとして検出）
- 分割表の**パート単位編集**（カーソルのあるパートだけを差し替え、div 行・他パート・
  外側の `.landscape` には触れない）
- セル結合 / 解除（rowspan・colspan）
- 出力形式の自動判定 — 結合を `merge-cols` で完全再現できるかシミュレーションし、
  再現できるときだけ選択肢として提示。既定はグリッド表
- 属性の編集（`caption` / `label` / `widths` / `.unnumbered`）
- ヘッダ行数 0〜N（マルチヘッダはグリッド表で出力）
- 列ごとの揃え（左 / 中央 / 右）
- Excel からの TSV 貼り付け
- 生成 Markdown のプレビュー
- 完全オフライン動作

#### 検証済みの挙動

Quarto 同梱の pandoc と `design-doc.lua` に通して確認しています。

- グリッド表の桁は**文字数ではなく表示幅**（東アジア全角=2）で数える
- グリッド表のセル内改行は**行末バックスラッシュ**（native な LineBreak になり、
  PDF でも改行され、後続行に余分な空白が入らない）
- グリッド表出力と `merge-cols` 出力は、テンプレートを通すと**同一の描画結果**になる

#### 既知の制限

- 分割表のパート区切りは変更できません（読み込み・保持のみ）
- 分割表では div 属性を編集できません（変更すると全パートに影響するため）
- `.landscape` は保持のみで、UI からの付け外しはできません
- Excel の結合は取り込みません（`text/plain` の TSV のみ）
- IPO 図（`.ipo`）、旧記法 `.split-table` / `.merge-rows` は対象外です
- 表を開いたあとに**ファイルが外部で変更されると Apply を拒否**します
  （行番号がずれた状態で書き戻すと別の場所を壊すため）。表を開き直してください
