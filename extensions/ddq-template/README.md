# DDQ Template

設計書テンプレート（[design-doc-quarto-template](../../README.md)、略称 ddq）で書く設計書のための
VSCode 拡張です。旧 **DDQ Revision**（ラベル付け・改訂履歴）と旧 **DDQ Table Editor**（表エディタ）を
1 本にまとめました（設計は [docs/ddq-template-study.md](../../docs/ddq-template-study.md)）。

- **作成** … 設計書リポジトリを新しく作る（`ddq init`）
- **発行** … `ddq pdf` / `ddq html` / `ddq diagrams` を VSCode から実行する
- **ラベル一覧** … 見出し・表・図の Quarto ラベルを一覧し、無いものに付ける
- **改訂履歴** … 見出し・表・図の単位で変更を並べ、修正内容を書いて改訂履歴表を作る
- **表エディタ** … 統一テーブル記法 `::: {.tbl …}` を表計算のように編集する

旧拡張（`ramsesyok.ddq-revision` / `ramsesyok.ddq-table-editor`）が入っていると、起動時に
アンインストールを案内します。同じファイルに既定の編集画面が 2 つ登録され、メニューも重複するためです。

## 使うもの

発行・ラベル一覧・改訂履歴には `ddq` が要ります。文書の解釈はすべて ddq が行い、この拡張は
画面と書き戻しだけを担当します。使う ddq は次の順に決まります。

1. 設定 **`ddqTemplate.ddqPath`**（指定すれば最優先。チームで ddq の版を固定したいときなど）
2. 拡張に同梱した `ddq.exe`（Windows x64 向けの VSIX に入っています）
3. `PATH` の `ddq`

PDF / HTML には **Quarto** も要ります。見つからないときは案内が出ます。インストール直後で
`PATH` が反映されていないときは、VSCode を開き直すか、設定 **`ddqTemplate.quartoPath`** に
`quarto.exe` のパスを入れてください。

表エディタは ddq を使いません。

信頼されていないワークスペース（制限モード）では動きません（ワークスペースで ddq を実行するため）。

## 設計書リポジトリを作る

コマンドパレットで **DDQ: 設計書リポジトリを作成**。フォルダを開いていないときは、
エクスプローラの **設計書リポジトリを作成** ボタンからも始められます。

| 開いているもの | 動き |
|---|---|
| 何も開いていない | 作る場所（親フォルダ）→ リポジトリ名 → 執筆フォルダ名（既定 `docs`）を選ぶと作成し、そのフォルダを開き直します |
| 空のフォルダ | 執筆フォルダ名を選ぶと、そのフォルダに作ります（`.git` `.vscode` `README.md` などだけなら空とみなします） |
| ほかのファイルがあるフォルダ | 「このフォルダに作る」か「別の場所に新しく作る」かを選びます（既存のファイルは上書きしません） |
| 既に設計書リポジトリ | 作りません |

作り終えると `_quarto.yml` が開き、**Git リポジトリとして初期化** のボタンが出ます。
Quarto が無くても作れます（最後の確認の `quarto render` を省きます）。

## 発行（PDF / HTML / 図）

執筆フォルダ（`_quarto.yml` と `.template-version` のあるフォルダ）に対して ddq を実行します。

| コマンド | 内容 |
|---|---|
| **DDQ: PDF を作成** | `ddq pdf`。終わると「PDF を開く」が出ます |
| **DDQ: HTML を作成** | `ddq html`。終わると「HTML を開く」が出ます |
| **DDQ: 図を変換** | `ddq diagrams`（`diagrams/` の `.mmd` / `.puml` を `.svg` に） |

- エクスプローラで**執筆フォルダを右クリック**しても実行できます（執筆フォルダにだけ出ます）
- 執筆フォルダの中のファイルを開いていると、**ステータスバーに `PDF: <執筆フォルダ名>`** が出ます。
  押すとその執筆フォルダの PDF を作ります
- 出力は「出力」パネルの **DDQ** に流れます。進捗の通知から**キャンセル**できます
- 同じ執筆フォルダでは 1 本ずつしか実行できません（`_book/` や図のキャッシュを同時に書き換えないため）

### テンプレートの版が合わないとき

ddq は、執筆フォルダの機構ファイル（`design-doc.lua` など）が自分の版と一致しないと止まります。
このとき拡張は版を比べて案内を出します。

| 状態 | 案内 |
|---|---|
| 執筆フォルダの方が古い | **ddq update を実行** → 機構ファイルを新しい版にしてから、元のコマンドをやり直します。変わったファイルはコミットしてください |
| 版は同じで機構ファイルが手で直されている | **ddq update を実行** で元に戻せます（差分は Git で確認してください） |
| 執筆フォルダの方が新しい | update は出しません（機構を古い版に戻してしまうため）。拡張（または `ddqTemplate.ddqPath` の ddq）を更新してください |

## ラベル一覧

改訂履歴をページ単位ではなく「見出し・表・図」単位で作るには、その 3 者を一意に指す
キーが要ります。キーは Quarto のラベル（`{#sec-x}` / `label="tbl-x"` / `{#fig-x}`）を
そのまま使います。改訂で見出し文言やキャプションが変わってもラベルは変わらないので、
版をまたいだ対応付けが安定し、改訂履歴表からは `@sec-x` でそのままリンクになります。

コマンドパレットで **DDQ: 見出し・表・図のラベルを一覧する**（エクスプローラで
執筆フォルダを右クリックしても開けます）。

| 列 | 内容 |
|---|---|
| ☑ | 書き戻す行（ラベルの無いものだけ既定でオン） |
| ファイル・行 | 押すとその行を横に開く |
| 種別 | 見出し（深さ）／表／IPO／表(pipe)／図 |
| 名称 | 見出しの文言・表のキャプション |
| ラベル | 付いていればその値、無ければ**候補**（書き換えられる） |

候補は `ddq` が内容から決めるハッシュ（`sec-3f9a1c` など）です。**人が読みやすい名前に
書き換えてから**書き戻すのがおすすめです（`@sec-purpose` のように本文から参照するため）。

**書き戻す**を押すと、チェックした行のラベルを元の文書に足します。

- 変更は `WorkspaceEdit` 1 つにまとまるので、**Ctrl+Z ひと押しで全部戻せます**
- 未保存のバッファにも当たります（保存するかどうかは人が決めます）
- 挿入は 1 行の中だけで、行は増減しません

次のものは候補を出しません（理由を列に出します）。

- **キャプションの無い `::: {.tbl}`** … 採番されない表なので、ラベルを付けても参照できません
- **`::: {#fig-…}` で包んでいない図** … 包み直すのは文書の構造を変える操作なので、機械では行いません

## 改訂履歴

コマンドパレットで **DDQ: 新しい改訂を始める（差分を取る）**。前回の改訂タグ
（`rev-<記号>`）と作業ツリーを比べ、`revisions/rev-<記号>.yml` を作って編集画面で開きます。
既にあるファイルを開くときは、エクスプローラで `revisions/rev-B.yml` を選ぶだけです。

画面は**見出し・表・図の単位**で変わった箇所を並べます。

| 列 | 内容 |
|---|---|
| 種別 | 変更／追加／削除／改名 |
| 箇所 | 名称（押すとその行を横に開く）とラベル |
| 差分 | VSCode の差分エディタで旧版と並べて見る（編集画面の隣に、その行で開く） |
| 修正内容 | **何のために、どこを直したか**を書く欄（改訂履歴に載ります） |

- **差分を取り直す** … 本文を直したあとに押すと差分を取り直します。**書いたメモは残ります**。
  「箇所」「差分」で移る行も、このとき取り直した位置になります（本文を直したあとはずれることがあります）
  （差分から消えたのにメモが残っているものは下段に分けて出るので、要らなければ消せます）
- **表を作る** … `revisions/history.qmd` を作ります。`index.qmd` の前付けから include して使います
- **確定する** … 表を作り直し、次に打つ Git コマンド（`git add … && git commit … && git tag rev-B`）を
  案内します。**コミットとタグは人が打ちます**

`rev-<記号>` のタグがあるファイルは確定済みとして編集できません。直すときは
`git tag -d rev-<記号>` でタグを消してください。

### 執筆フォルダだけを開いているとき（差分が出ない）

「差分」は旧版を VSCode 内蔵の Git 拡張から読みます。**執筆フォルダ（例: `docs/cli-impl`）
だけを VSCode で開くと、リポジトリの本体はその上のフォルダにある**ため、内蔵 Git 拡張は
設定 **`git.openRepositoryInParentFolders`** に従ってしか開きません。

| 設定値 | 動き |
|---|---|
| `prompt`（既定） | 開いた直後に「親フォルダのリポジトリを開きますか？」と通知が出る。**「はい」を押すまで開かれない** |
| `always` | 黙って開く（おすすめ） |
| `never` | 開かない |

開かれていないまま「差分」を押すと、**リポジトリを開いて差分を見る**／**設定を開く**の
案内が出ます。前者はそのウィンドウの間だけリポジトリを開きます。毎回聞かれないようにするには、
執筆フォルダの `.vscode/settings.json` に次を書いてください。

```json
{
  "git.openRepositoryInParentFolders": "always"
}
```

リポジトリのルートを VSCode で開いている場合は、この設定は要りません。

## 表エディタ

セルを結合しながら表を組み立て、**結合が無ければ通常のパイプ表**、**結合があれば
グリッド表または `merge-cols`** として `.tbl` ブロックを書き出します。

### 機能

- **`.tbl` ブロックの再編集**: `::: {.tbl …}` の中にカーソルを置いてコマンドを実行
- **分割表のパート単位編集**: div 内に複数の表があるときは、**カーソルのあるパートだけ**を差し替え
- **セル結合 / 解除**: 矩形選択して結合。rowspan / colspan の両方に対応
- **出力形式の自動判定**: 結合を `merge-cols` で完全再現できるかシミュレーションし、
  再現できるときだけ `merge-cols` を選択肢として出す（既定はグリッド表）
- **属性の編集**: `caption` / `label` / `widths` / `.unnumbered`
- **ヘッダ行数の指定**: 0〜N 行（マルチヘッダはグリッド表で出力）
- **列ごとの揃え**: 左 / 中央 / 右
- **Excel からの貼り付け**: TSV を Ctrl+V
- **Excel 風の操作**: キーボード移動・ドラッグ範囲選択・右クリックメニュー・Undo/Redo
- **Markdown プレビュー**
- **完全オフライン動作**: CDN・インターネット接続は不要

### 使い方

1. `.qmd` または `.md` を開く
2. 右クリックメニュー、またはコマンドパレットから **DDQ: 表エディタを開く**
3. 表を編集し、**Apply** でドキュメントへ反映

カーソル位置によって、開かれる対象が変わります。

| カーソル位置 | 動作 |
|--------------|------|
| `::: {.tbl …}` の中 | そのパートを読み込んで再編集 |
| 素のパイプ表／グリッド表の上 | 取り込み、Apply 時に `::: {.tbl}` で囲む |
| それ以外 | 新規作成してカーソル位置に挿入 |

### セル操作

Excel / Handsontable と同じ流儀です。

| 操作 | 方法 |
|------|------|
| セル選択・移動 | クリック、矢印キー、Tab / Shift+Tab、Home / End（Ctrl 付きで表の端） |
| 範囲選択 | ドラッグ、Shift+クリック、Shift+矢印、選択の右下の ■ をドラッグ、Ctrl+A で全体 |
| セル編集 | 文字を打つ（内容を置き換え）、Enter / F2 / ダブルクリック（末尾に追記） |
| セル内改行 | Alt+Enter |
| 編集確定 | Enter（下へ移動）、Tab（右へ移動）、別のセルをクリック |
| 編集キャンセル | Escape |
| 内容を消去 | Delete / Backspace |
| 元に戻す／やり直す | Ctrl+Z ／ Ctrl+Y（Ctrl+Shift+Z） |
| 行・列の挿入 | 右クリックメニュー（上／下、左／右）、またはツールバー |
| コピー／貼り付け | Ctrl+C ／ Ctrl+V（選択なしの Ctrl+V は Excel の表を丸ごと取り込み） |

### 出力例

#### 結合なし → パイプ表

```markdown
::: {.tbl caption="機能分類" label="tbl-cls" widths="20,20,60"}
| 大分類 | 中分類 | 項目         |
| ------ | ------ | ------------ |
| 受注   | 登録   | 入力チェック |
| 受注   | 引当   | 在庫確認     |
:::
```

#### 結合あり → グリッド表（既定）

```markdown
::: {.tbl caption="機能分類" label="tbl-cls" widths="20,20,60"}
+--------+--------+--------------+
| 大分類 | 中分類 | 項目         |
+========+========+==============+
| 受注   | 登録   | 入力チェック |
+        +--------+--------------+
|        | 引当   | 在庫確認     |
+--------+--------+--------------+
:::
```

#### 結合あり → merge-cols（再現可能なときだけ選択可）

```markdown
::: {.tbl caption="機能分類" label="tbl-cls" widths="20,20,60" merge-cols="1"}
| 大分類 | 中分類 | 項目         |
| ------ | ------ | ------------ |
| 受注   | 登録   | 入力チェック |
| 受注   | 引当   | 在庫確認     |
:::
```

上の 2 つは**テンプレートを通すと同じ描画結果**になります（どちらも `rowspan="2"`）。

### `merge-cols` が選べない場合

`merge-cols` は「縦に連続する同一値を自動で rowspan 結合」する再生成型の指定なので、
任意の結合を表現できるとは限りません。次の場合は自動的にグリッド表へ寄せ、理由を表示します。

- 横方向の結合（colspan）がある
- ヘッダが 0 行または 2 行以上
- 空セルが結合されている
- 同じ値が連続する箇所が意図せず結合されてしまう
- 左の列が結合されておらず、連鎖ルールで再現できない
- 分割表である（`merge-cols` は div 全体＝すべてのパートに影響するため）

### 制限

- **分割表のパート区切りは変更できません**（読み込み・保持のみ）
- **分割表では div 属性を編集できません**（変更すると全パートに影響するため）
- **`.landscape` は保持のみ**。UI からの付け外しはできません
- Excel の**結合は取り込みません**（`text/plain` の TSV のみ）
- IPO 図（`.ipo`）、旧記法 `.split-table` / `.merge-rows` は対象外です

詳しい仕様は [tableEditor-requirements.md](tableEditor-requirements.md) を参照してください。

## 開発

VSCode で**この `extensions/ddq-template/` フォルダを開き**（リポジトリのルートではなく）、
`F5`（**Run Extension**）で拡張開発ホストを起動します。起動前に `npm: build` が自動で走り、
`sample/` フォルダを開いた状態で立ち上がります。

```bash
npm install
npm run verify      # 型検査・テスト・ビルド・オフライン検査・脆弱性検査
npm run test:host   # 実拡張ホストでの検証
npm run package     # VSIX を作る（ddq.exe なし。開発・CI 用）
```

配布する VSIX は ddq.exe を同梱したターゲット指定の版で、`ddq release` が作ります
（exe を `bin/win32-x64/ddq.exe` にコピーしてから `npm run package:win32-x64`）。手で作るときは:

```bash
npm run package:win32-x64   # bin/win32-x64/ddq.exe を置いてから。ddq-template-win32-x64-<版>.vsix ができる
npm run test:smoke          # その VSIX を展開した中身で VSCode を起動し、同梱 ddq で init → html を通す
```

| コマンド | 内容 |
|----------|------|
| `npm test` | ユニットテスト（pandoc があれば pandoc 連携テストも実行） |
| `npm run typecheck` | 拡張ホストと Webview の型チェック |
| `npm run build` | 拡張ホスト（esbuild）と Webview 2 画面（vite。`--mode revision` / `--mode tableEditor`）のビルド |
| `npm run check:offline` | 配布物に通信 API・外部 URL が無いことを検査 |
| `npm run check:audit` | 本番依存の脆弱性（0 件必須） |

### 実拡張ホストでの検証

`npm run test:host` は一時フォルダに検証用の執筆フォルダを作り、専用のプロファイルで
VSCode を起動して、一覧が開くこと・書き戻しが当たること・Undo で戻ることを確かめます。

- **VSCode**: インストール済みのものがあればそれを使います（通信しません）。無い場合だけ
  `@vscode/test-electron` がテスト用の VSCode を取得します（CI 用。`.vscode-test/` に入り、
  **配布物には一切入りません**）
- **ddq**: `../../cli/target/release/` にあればそれを、無ければ `tests/host/fake-ddq.mjs`
  （実物の出力を採取した golden を返す差し替え）を使います。引数や `DDQ_BIN` でも渡せます

### pandoc 連携テスト

`src/tableEditor/formats/pandoc.test.ts` はグリッド表の記法が pandoc の解釈と一致するかを
**本物の pandoc** に通して確かめます。pandoc が無い環境では自動でスキップされるので、
オフライン環境でも `npm test` は通ります。特定の pandoc を使いたいときは環境変数
`PANDOC` にパスを指定してください。

### 表エディタのデバッグ用サンプル

`sample/tables.qmd` には検出パターンが一通り並んでいるので、表にカーソルを置いて
**DDQ: 表エディタを開く** を実行すると動作を確認できます。

| 節 | 確認できること |
|----|----------------|
| 1 | 通常の `.tbl`（属性を編集できる単一表） |
| 2 | `merge-cols="1,2"` の階層連鎖を展開して表示 |
| 3 | `merge-cols="2,3"`（1 列目の連番は結合しない） |
| 4 | グリッド表のマルチヘッダ・横結合 |
| 5 | 分割表のパート単位編集（属性は読み取り専用） |
| 6 | `.landscape` の入れ子（外側は保持のみ） |
| 7 | `.tbl` の外にある素の表の取り込み |
| 8 | 表が無い場所での新規作成 |
| 9 | セル内改行 |

ソースを直しながら試すときは、`npm: watch:ext` と `npm: watch:webview:*` タスクを走らせた
うえで **Run Extension (ビルドせずに起動)** を使うと、ビルド待ちなしで起動できます。

### CI

`../../.github/workflows/extension.yml` で GitHub Actions が動きます
（`extensions/` 配下の push / pull request、手動実行）。

版はテンプレートの版（`../../template/VERSION`）と揃えます。`ddq release` が照合し、
違っていれば止まります。テンプレートの版を上げたら `npm version <版> --no-git-tag-version`
でここも上げてください。

## 動作要件

- Visual Studio Code 1.85 以上
- ネットワーク接続不要（完全オフライン対応）

## 導入（利用者）

リリースページの `ddq-template-win32-x64-<版>.vsix`（ddq.exe 入り。配布 zip とは別の資産）を
VSCode の「VSIX からのインストール…」で入れます。Marketplace には公開していません。
